# xray-railway

Xray-core на Railway за сайтом-заглушкой. В браузере домен показывает обычный сайт маленькой мастерской; пути прокси отдаются только запросам, похожим на свой транспорт. Есть страница и лента подписки (для Incy и других клиентов).

## Что запускается
- **HTTPS-домен Railway (порт 8080)**: Caddy. `/ws`, `/xh`, `/grpc/*` уходят в Xray (VLESS по WS / XHTTP / gRPC), два секретных пути отдают страницу и ленту подписки (`sub.py`), всё остальное получает сайт-заглушка (`index.html`, `404.html` в корне репозитория).
- **TCP-прокси Railway**: VLESS + Reality поверх XHTTP (порт приложения 4443) и gRPC (5443). Включено по умолчанию, ключ выводится из UUID.
- **WARP (необязательно)**: выбранные категории сайтов идут через Cloudflare WARP.

## Настройки: ноль переменных
В Railway Variables **ничего задавать не нужно**. UUID создаётся автоматически: выводится из `RAILWAY_SERVICE_ID` и `RAILWAY_ENVIRONMENT_ID`, поэтому не меняется между деплоями (источник печатается в логе). Свой UUID можно задать переменной `UUID`. Вне Railway без `UUID` он случайный на каждый старт. Всё остальное лежит в `config.env` (в нём нет секретов) и попадает в образ. Переменная Railway с тем же именем важнее значения из файла, поэтому можно временно переопределить что угодно, не правя репозиторий. Какие значения переопределены, видно в логе (`overridden by Railway variables`).

Необязательные секреты, которые стоит хранить только в Railway Variables: `WARP_PRIVATE_KEY`, `REALITY_PRIVATE_KEY` (свой ключ вместо выводимого из UUID).

## Деплой
1. Сервис из этого репозитория (переменные не нужны). Все файлы лежат в корне, без папок: так их не потерять при загрузке через веб-интерфейс GitHub.
2. Networking -> Generate Domain, target port = 8080.
3. Networking -> два TCP-прокси: порт приложения 4443 и 5443.
4. Впишите адреса прокси в `config.env` ровно как их показывает Railway и сделайте redeploy:
   ```
   TCP_PROXY_XHTTP=host.proxy.rlwy.net:12345
   TCP_PROXY_GRPC=host.proxy.rlwy.net:23456
   ```
   Если у сервиса одна пара `RAILWAY_TCP_PROXY_*`, она подставится сама по порту приложения. Пока адрес не задан, Reality-ссылка в подписку не попадает, а в логе печатается шаблон.
5. Откройте `Subscription page` из деплой-лога и нажмите «Добавить в Incy».

## Reality-ключ из UUID
Приватный ключ считается детерминированно из UUID (`derive.py`), публичный ключ (`pbk`) и `sid` печатаются в логе. Минус: знающий UUID может вычислить и приватный ключ. Но UUID и так даёт доступ к прокси, а для подмены сервера нужно ещё перехватывать трафик к TCP-прокси. Смена UUID меняет ключ. Автоматический UUID выводится из ID сервиса Railway: они не публичны, но видны участникам проекта (при необходимости задайте свой `UUID`). Нужен независимый ключ: `xray x25519` и переменная `REALITY_PRIVATE_KEY`.

## Что в логе при старте
- UUID и его источник;
- сколько значений взято из `config.env` и что переопределено Railway;
- домен, включённые транспорты, `fp`;
- источник Reality-ключа, `pbk`, `sid`, SNI/dest;
- готовые ссылки WS / XHTTP / gRPC и Reality (или шаблон и подсказка, что вписать в `config.env`);
- адреса страницы и ленты подписки, лимит устройств, сохраняется ли привязка, список ссылок в подписке.

## Подписка
Пути `/s/<16 символов>` и `/f/<16 символов>` вычисляются из UUID (свои: `SUB_PAGE_PATH`, `SUB_FEED_PATH`). В ленте: WS, XHTTP и Reality-ссылки, для которых известен адрес TCP-прокси. Лимит устройств считается по заголовку `x-hwid` (`MAX_DEVICES`). Привязка хранится в `STATE_DIR`: подключите Railway Volume и задайте `STATE_DIR=/data`, иначе каждый redeploy её сбрасывает. Свой домен: `PUBLIC_DOMAIN`.

## Советы по клиенту
- Держите 1-2 долгих соединения, не открывайте залп параллельных хендшейков (mux/xmux с ограничением).
- Отпечаток `firefox` / `edge` / `android`, не `randomized`.
- XHTTP через edge Railway: `packet-up`. `stream-up` и `stream-one` требуют HTTP/2 до сервиса (на портах Reality TCP-прокси это нормально).
- Российские домены и IP направляйте напрямую.

## Ограничения
- У Railway нет входящего UDP: Hysteria2, WireGuard и Amnezia здесь не поднять.
- Мобильные белые списки это не решает: нужен RU-relay перед Railway.
- Bittorrent и частные диапазоны IP заблокированы.
- Проверьте условия Railway на проксирующий трафик.
